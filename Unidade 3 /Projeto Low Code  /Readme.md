# Projeto Módulo 3 – Low Code/No Code/Vibecode

# Desafio Escolhido

O projeto desenvolvido consiste em um site de catálogo de jogos chamado GameHub.

A proposta do sistema é funcionar de forma semelhante a uma biblioteca digital de jogos, permitindo visualizar jogos cadastrados, explorar informações sobre os jogos e adicionar novos jogos ao catálogo.

O objetivo principal do projeto foi desenvolver um protótipo funcional utilizando ferramentas no-code, sem a necessidade de programação tradicional.

---

# Protótipo

O protótipo foi desenvolvido utilizando a plataforma Bubble.

O sistema desenvolvido possui:

- Página inicial;
- Catálogo de jogos;
- Cadastro de jogos;
- Sistema de pesquisa;
- Organização dos jogos em formato de cards;
- Interface inspirada em plataformas digitais de jogos.

## Link do Protótipo

O protótipo pode ser acessado pelo link abaixo:

# Plataforma Utilizada

## Bubble

A plataforma Bubble foi escolhida por permitir a criação de aplicações web sem necessidade de programação tradicional.

A ferramenta possui uma interface visual intuitiva que facilita o desenvolvimento de páginas, formulários, banco de dados e componentes interativos utilizando lógica visual ao invés de código tradicional.

Além disso, a plataforma permite criar protótipos funcionais rapidamente, sendo uma boa alternativa para desenvolvimento de aplicações web simples e testes de ideias.

---

# Funcionalidades Implementadas

O sistema GameHub possui as seguintes funcionalidades:

- Página inicial do projeto;
- Navegação entre páginas;
- Catálogo de jogos;
- Sistema de pesquisa;
- Cadastro de novos jogos;
- Upload de imagem para os jogos;
- Exibição de jogos em formato de cards;
- Organização das informações em banco de dados interno.

---

# Vantagens Identificadas

1. Desenvolvimento rápido de protótipos;

2. Facilidade na criação de interfaces visuais;

3. Redução da necessidade de programação tradicional;

4. Banco de dados integrado na própria plataforma;

5. Facilidade para testar ideias rapidamente;

6. Interface intuitiva durante o desenvolvimento;

7. Possibilidade de criar aplicações funcionais com pouco conhecimento técnico.

---

# Limitações Encontradas

1. Algumas limitações de personalização visual;

2. Dependência da plataforma Bubble para manter o sistema online;

3. Menor liberdade técnica em comparação com programação tradicional;

4. Certas funcionalidades avançadas exigem maior adaptação da plataforma;

5. Algumas configurações possuem limitações em comparação ao desenvolvimento manual;

6. Recursos mais avançados podem exigir planos pagos;

7. Controle técnico mais limitado em algumas partes do sistema.

---

# Dificuldades Durante o Desenvolvimento

Durante o desenvolvimento do projeto, algumas dificuldades foram encontradas principalmente na organização das páginas e no entendimento da lógica de funcionamento da plataforma Bubble.

Também houve dificuldade inicial para configurar corretamente os componentes do catálogo e integrar as informações cadastradas ao banco de dados interno da plataforma.

Outra dificuldade encontrada foi ajustar a organização visual dos cards e das páginas para deixar o site mais próximo da proposta visual inspirada em plataformas digitais de jogos.

Além disso, algumas funcionalidades precisaram ser adaptadas às limitações da plataforma, principalmente em relação à personalização mais avançada da interface.

---

# Dependências da Plataforma

O projeto depende diretamente da plataforma Bubble para funcionamento e hospedagem do sistema.

Isso significa que:

- o funcionamento do site depende dos serviços da plataforma;
- determinadas funcionalidades estão limitadas ao que a ferramenta oferece;
- algumas configurações dependem das opções disponibilizadas pelo Bubble;
- existe menor controle técnico interno quando comparado ao desenvolvimento tradicional.

Mesmo assim, a plataforma se mostrou eficiente para criação rápida de protótipos funcionais.

---

# Reflexão Crítica

Durante o desenvolvimento do GameHub, foi possível perceber como ferramentas no-code podem acelerar bastante a criação de aplicações web.

Mesmo sem utilizar programação tradicional, foi possível criar um site funcional contendo catálogo de jogos, cadastro de novos jogos, sistema de pesquisa e navegação entre páginas.

A experiência também mostrou como plataformas no-code facilitam o desenvolvimento inicial de projetos e ajudam bastante na criação rápida de protótipos.

Por outro lado, também foi possível perceber algumas limitações relacionadas à personalização mais avançada, dependência da plataforma e menor liberdade técnica quando comparado ao desenvolvimento utilizando código tradicional.

Mesmo com essas limitações, a experiência foi positiva e demonstrou como ferramentas no-code podem ser úteis para criação rápida de aplicações acadêmicas e protótipos funcionais.
